# Step 0 — 询问用户目标日期的总工作时长与工作开始时间

这是整个流程的**第一步**，必须在收集 session 或 Jira issue 之前完成。用户输入的总工时作为后续耗时校准的**唯一基准**；开始时间作为后续为每个 issue 生成连续 `started` 时间线的基准。

> **目标日期**：默认今天（`--date` 未指定）。传了 `--date 2026-10-25` 时，下面两问的
> 「你」指的是**那一天**，不要问成「今天」，也不要把目标日期悄悄换成今天。

1. 通过 `ask_user_question` 依次向用户询问（把 `<目标日期>` 换成实际日期，今天就说「今天」）：
   - 问题 A："<目标日期>你实际工作了多长时间？（例如 8h、7.5h、6h）"
   - 问题 B："<目标日期>从几点开始工作？（默认 9:00，例如 9:00、8:30、13:00）"
2. 解析用户回答：
   - 总工时记录为 `total_working_hours`（统一换算为分钟：`total_working_minutes`）。
   - 开始时间记录为 `work_start_time`（格式 `HH:MM`，默认 `09:00`，本地时区）。
3. 接受常见格式：
   - 总工时：`8h`、`8 h`、`8小时`、`7.5h`、`7小时30分`、`7:30`、`30m`
   - 开始时间：`9:00`、`9点`、`09:00`、`8:30`、`13:00`、`13:30`、`下午1点`
4. 如果用户跳过或拒绝回答：
   - 总工时未回答：`total_working_minutes` 回退到 `sum_initial_minutes`，并在最终报告头部标注"用户未确认总工时，以下耗时由 skill 自动估算"。
   - 开始时间未回答：`work_start_time` 默认回退到 `09:00`。

**约束**：
- Step 4 校准后，所有 `matched_sessions` 的修正工时之和必须等于 `total_working_minutes`。
- Step 4 时间线分配后，每个 issue 的 `started_at` 必须连续且不重叠，并扣除 12:00–13:00 午休时间。
